📚 什麼是 SQL Injection？

SQL Injection（SQL 注入）是一種常見的 Web 應用程式安全風險。 當網站將使用者輸入直接組合進 SQL 查詢時， 攻擊者可能透過特殊輸入改變原本 SQL 語句的語意。

🧠 SQL Injection 六種常見教學類型

1 Login Bypass

利用輸入內容改變登入查詢條件。

2 UNION-based

利用 UNION 將其他 SELECT 結果合併。

3 Boolean Blind

透過 True / False 回應差異推測資料。

4 Time-based Blind

透過資料庫延遲行為觀察條件是否成立。

5 ORDER BY

ORDER BY 的欄位名稱不能單純使用一般參數化方式處理。

6 WAF

WAF 可以作為防禦層，但不能取代安全的 SQL 程式設計。

🛡️ 防禦策略

① Prepared Statement

讓 SQL 結構與使用者資料分離。

② Input Validation

確認輸入資料是否符合預期格式。

③ Least Privilege

資料庫帳號只授予必要權限。

④ Error Handling

避免把資料庫詳細錯誤直接回傳給使用者。

⑤ Logging

記錄異常行為，協助事件分析。

⑥ WAF

作為額外防護層，但不是唯一防禦措施。

🔑 Prepared Statement 的概念

❌ 不安全寫法

sql = "SELECT * FROM users WHERE name = '" + username + "'";

✅ 建議寫法

sql = "SELECT * FROM users WHERE name = ?";

cursor.execute(sql, (username,))
重點： Prepared Statement 將 SQL 結構與資料參數分開， 可防止使用者輸入被當成 SQL 語法執行。

⚠️ ORDER BY 為什麼需要 Whitelist？

一般資料值可以使用 Prepared Statement， 但欄位名稱、排序方向等 SQL 結構元素通常不能直接用一般參數取代。 

const allowedColumns = [
    "name",
    "email",
    "created_at"
];

if (!allowedColumns.includes(sortColumn)) {
    throw new Error("Invalid column");
}

const sql =
    `SELECT * FROM users
     ORDER BY ${sortColumn}`;
核心概念： SQL 結構使用固定允許清單， 使用者資料則使用參數化查詢。
