SQL Injection 資安教學平台

SQL Injection（SQL 注入）是一種常見的 Web 應用程式安全問題。 當程式將使用者輸入直接組合進 SQL 指令時， 攻擊者可能改變原本 SQL 語句的語意。

本平台使用瀏覽器端模擬資料庫環境， 讓學生了解「輸入 → SQL → Parser → Database」 之間的關係，而不會連接真實網站或資料庫。

1️⃣ Login Bypass

當登入程式使用字串串接 SQL， 惡意輸入可能改變 WHERE 條件。 

SELECT *
FROM users
WHERE username = 'USER'
AND password = 'PASSWORD';

2️⃣ UNION-based SQL Injection

UNION 可以將另一個 SELECT 查詢的結果 加入原本查詢結果。 

SELECT id,name
FROM users

UNION

SELECT id,name
FROM products;

教學重點： UNION 查詢通常需要注意欄位數量與資料型別相容性。

3️⃣ Boolean Blind SQL Injection

當網站不直接顯示資料時， 可以透過 True / False 的頁面差異觀察結果。 

Condition = TRUE
→ 頁面正常

Condition = FALSE
→ 頁面不同

4️⃣ Time-based Blind

某些情況下，攻擊者可能透過資料庫延遲行為， 觀察回應時間差異。 

正常：
Response ≈ 100 ms

條件成立：
Response ≈ 3000 ms

5️⃣ ORDER BY Injection

ORDER BY 的欄位名稱不是一般資料值， 因此不能單純把它當成一般參數處理。

正確方法通常是使用「白名單」限制可接受欄位。

6️⃣ WAF

Web Application Firewall 可以作為額外防禦層， 但不應取代安全的 SQL 查詢設計。

真正的核心防禦仍應包含參數化查詢、 輸入驗證與最小權限。

🛡️ 防禦策略

① Parameterized Query

使用參數化查詢， 將資料與 SQL 指令分離。

② Input Validation

確認資料格式、長度與允許範圍。

③ Least Privilege

資料庫帳號只授予必要權限。

④ Error Handling

避免直接將資料庫錯誤訊息提供給使用者。

⑤ Logging

記錄異常查詢與安全事件。

⑥ WAF

作為額外的防禦層。

🔐 SQL Injection 防禦程式碼

以下示範不同程式語言如何使用安全的資料庫查詢方式。

🐍 Python SQLite

import sqlite3

conn = sqlite3.connect("demo.db")

username = input("Username: ")
password = input("Password: ")

sql = """
SELECT *
FROM users
WHERE username = ?
AND password = ?
"""

cursor = conn.execute(
    sql,
    (username, password)
)

result = cursor.fetchall()

print(result)
重點： 使用 `?` 參數， 資料不會直接被當成 SQL 語法解析。

🐘 Python PostgreSQL

import psycopg2

conn = psycopg2.connect(
    host="localhost",
    database="demo",
    user="app",

cur = conn.cursor()

    AND password = %s

rows = cur.fetchall()

print(rows)

↕️ ORDER BY 白名單

ORDER BY 欄位名稱通常不能直接用一般 SQL parameter 取代，因此可以使用白名單。 

const allowedColumns = {
    name: "name",
    price: "price",
    created: "created_at"
};

const sort =
    allowedColumns[userInput] || "name";

const sql =
    `SELECT * FROM products
     ORDER BY ${sort}`;
⚠️ 這裡的核心是： 只有程式預先定義的欄位名稱 才能進入 SQL。
