SQL Injection 資安教學與防禦實驗室

SQL Injection（SQL 注入）是一種因為應用程式錯誤地將「使用者輸入」 與「SQL 語法」混合，而造成資料庫查詢結構可能被改變的漏洞。 本平台使用虛擬資料庫與瀏覽器模擬進行教學， 不連接真實資料庫。

漏洞的核心並不是「使用者輸入了特殊字元」本身，而是應用程式 讓輸入資料有機會被資料庫解析成 SQL 語法。

🔑 Login Bypass

利用輸入內容改變登入查詢的邏輯，使原本的帳號密碼驗證條件失去原本意義。

🔗 UNION-based

利用 UNION 將另一個 SELECT 查詢結果加入原本的查詢結果。 教學時應理解欄位數量與資料型別相容等限制。

👁 Boolean Blind

當頁面沒有直接顯示資料時，可以觀察 True / False 所造成的不同應用程式反應。

⏱ Time-based Blind

透過資料庫延遲行為推測條件結果。本平台只模擬延遲效果，不會真的讓資料庫 Sleep。

↕ ORDER BY

ORDER BY 的欄位名稱通常不能直接使用一般參數化方式處理， 因此需要使用「白名單」限制允許的排序欄位。

🧱 WAF

WAF 可以作為額外防線，但不應取代 Prepared Statement、輸入驗證、 權限控制等根本性防禦。

02｜漏洞形成的關鍵

❌ 危險方式

username = request.form["username"] sql = "SELECT * FROM users WHERE username = '" \ + username + "'" db.execute(sql)

問題：使用者輸入直接進入 SQL 語法字串。

✅ 安全方式

username = request.form["username"] sql = """ SELECT * FROM users WHERE username = ? """ db.execute(sql, (username,))

參數值與 SQL 結構分離。

參數化查詢的核心概念是讓 SQL 結構與參數值分開處理。 因此，輸入內容中的 SQL 關鍵字、引號等文字不會直接改變 已建立的 SQL 結構。

注意： 參數化查詢主要解決「資料值被當成 SQL 語法」的問題。 例如動態 ORDER BY 欄位名稱、表名等 SQL identifier， 仍需要使用白名單或安全的程式設計方式處理。

05｜防禦策略

1. Parameterized Query

SQL 結構與參數值分離。

2. Input Validation

限制格式、長度與允許值。

3. Least Privilege

資料庫帳號只取得必要權限。

4. Error Handling

避免把資料庫詳細錯誤直接顯示給使用者。

5. Logging

記錄異常請求與安全事件。

6. WAF

作為額外防禦層，而不是唯一防禦方式。

🔐 Secure Coding 防禦實驗室

比較「字串串接」與「參數化查詢」的程式設計方式， 並了解不同程式語言的安全寫法。

🐍 Python SQLite

❌ Dangerous

sql = "SELECT * FROM users WHERE name = '" + name + "'" cursor.execute(sql)

✅ Secure

sql = """ SELECT * FROM users WHERE name = ? """ cursor.execute(sql, (name,))

🐍 Python PostgreSQL

sql = """ SELECT * FROM users WHERE username = %s """ cursor.execute( sql, (username,) )

🟢 Node.js mysql2

const sql = ` SELECT * FROM users WHERE username = ? `; connection.execute( sql, [username] );

🐘 PHP PDO

$stmt = $pdo->prepare( "SELECT * FROM users WHERE username = :username" ); $stmt->execute([ ':username' => $username ]);

☕ Java JDBC

String sql = "SELECT * FROM users WHERE username = ?"; PreparedStatement ps = connection.prepareStatement(sql); ps.setString(1, username); ResultSet rs = ps.executeQuery();

↕ ORDER BY 安全寫法

allowed = { "name": "name", "date": "created_at", "id": "id" } column = allowed.get(user_input) if column is None: column = "id" sql = "SELECT * FROM users ORDER BY " + column

這裡不是把欄位名稱直接當參數，而是先限制可接受的欄位。
